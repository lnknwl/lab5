# Устройство программы

## Классы из третьей работы

Complex хранит действительную и мнимую части числа, считает существующие объекты и выполняет операции. Calculator хранит текущее число и историю успешных операций

Префиксные и постфиксные ++ и -- меняют действительную часть на один. Есть обычные и составные арифметические операции. Сравнения <, >, <= и >= используют модули, а == и != сравнивают обе части числа

Деление на ноль, бесконечные значения и переполнение обрабатываются исключениями. При неудачной операции текущее число и история сохраняются

## Файлы

- include/Complex.h и src/Complex.cpp — комплексное число
- include/Calculator.h и src/Calculator.cpp — калькулятор и меню
- include/Lab3Api.h — обозначение функций для экспорта и импорта
- clients/main.cpp — общая точка входа двух программ
- tests/Tests.h и tests/Tests.cpp — общие автоматические проверки
- tests/verify.ps1 — сравнение результатов и способов линковки

Проверки отделены от main.cpp. Без аргументов клиент открывает меню, с --test выполняет проверки. В библиотеке нет main(), поэтому ее можно подключать к разным программам

## Экспорт и импорт

В объявления классов и свободных функций добавлен LAB3_API. Он раскрывается по-разному при сборке:

| Флаги | Значение LAB3_API |
| --- | --- |
| Без LAB3_SHARED | Пустое объявление для статической библиотеки |
| LAB3_SHARED и LAB3_BUILD | __declspec(dllexport), функции экспортируются из DLL |
| Только LAB3_SHARED | __declspec(dllimport), клиент импортирует функции из DLL |

Определение оператора присваивания Complex перенесено из заголовка в Complex.cpp. Поведение осталось прежним, но реализация теперь находится в библиотеке

Статическая переменная Complex::objectCount определяется в Complex.cpp. В динамическом варианте она находится внутри DLL, клиент получает ее значение через экспортированный getObjectCount(). Отдельной копии счетчика в клиенте нет

## Два способа линковки

В статическом варианте нужный код берется из liblab3.a при сборке exe. При запуске исходный архив не нужен

В динамическом варианте при линковке используется lab3.lib. Это библиотека импорта: в ней находится информация о подключении функций, а реализация остается в lab3.dll. Во время запуска Windows загружает DLL

Статическая библиотека и библиотека импорта не взаимозаменяемы. Расширение .lib у импортной библиотеки соответствует заданию для Windows; файл создан инструментами MinGW и используется с этим же компилятором

Оба клиента собираются одним компилятором и используют совместимую среду C++. Это нужно, потому что через границу DLL передаются строки, контейнеры, потоки и исключения C++

## Проверка результата

Взятые из третьей работы проверки запускаются для обоих способов линковки. Они охватывают конструкторы, копирование, счетчики, операции, исключения, историю и ввод

verify.ps1 дополнительно сравнивает вывод клиентов на одинаковом вводе и смотрит таблицы импорта через objdump. У динамического клиента есть зависимость от lab3.dll, у статического ее нет. Для запуска клиентов каталог компилятора исключается из PATH
